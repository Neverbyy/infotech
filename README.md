# Каталог книг — фронтенд

Тестовое задание на позицию Frontend-разработчика, «Инфотек».

SPA-каталог книг и авторов поверх REST API, описанного в [`api/book.yaml`](api/book.yaml).
Макета не было — интерфейс и вся визуальная система собраны с нуля.

**Стек:** Vue 3 (Composition API, `<script setup>`) · TypeScript (strict) · Pinia · Vue Router · Vite · CSS без UI-библиотек.

---

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173`. Бэкенд не нужен: по умолчанию в dev-режиме запросы
перехватывает мок-сервер на [MSW](https://mswjs.io), реализующий весь `book.yaml`.

**Демо-доступ:** логин `user`, пароль `password` (кнопка «Подставить» есть на странице входа).

Данные мока живут в `localStorage` и переживают перезагрузку. Сбросить — кнопка
«Сбросить данные» в подвале.

**SMS-уведомления работают из коробки** — на ключе-эмуляторе SMSPILOT: запросы
реально уходят на шлюз, но сообщения не отправляются и не тарифицируются.
Как посмотреть: подписаться на автора → войти как `user` → добавить книгу этого
автора → открыть «Подписки». Подробности в разделе
[SMS-уведомления о новинках](#sms-уведомления-о-новинках).

### Подключение реального бэкенда

```dotenv
# .env.development.local
VITE_USE_MOCK=false
VITE_API_BASE_URL=/api/v1
VITE_API_PROXY_TARGET=http://localhost:8080   # чтобы dev-сервер проксировал /api и не ловил CORS
```

Имя файла важно: у Vite файл под конкретный режим (`.env.development`) приоритетнее
общего `.env.local`, поэтому переопределять нужно именно `.env.development.local`.

Больше ничего менять не нужно: HTTP-клиент и сторы про мок не знают.

## Ключевые решения

**Свой HTTP-клиент вместо axios.** Нужны Bearer-токен, конверт `{ success, data }`,
разбор `errors[]` и обработка 401 ошибки

**`ApiError` как единый способ говорить об ошибке.** Класс несёт статус и `errors[]`
из спеки, а геттеры `fieldErrors` / `generalErrors` раскладывают ответ 422 на подсветку
конкретных инпутов и общий блок над формой. Компонентам не нужно знать про HTTP.

**Токен хранится в `http.ts`, а не в сторе.** Иначе получаем цикл импортов
`api → store → api`. Стор авторизации кладёт токен через `setAuthToken` и вешает
разлогин на 401 через `setUnauthorizedHandler`.

**Отмена гонок в списках.** Быстрый ввод в поиске порождает несколько запросов;
`AbortController` в сторах гарантирует, что список не «мигнёт» устаревшим ответом.

**Фильтры — в URL, а не в состоянии компонента.** Единственный источник истины —
query-параметры, сторы просто реагируют на них.

**Валидация на клиенте и на сервере.** Клиентская даёт мгновенную реакцию
(включая контрольную сумму ISBN-10/13), серверные 422 имеют приоритет и подсвечивают
те же поля.

**CSS без фреймворка.** Дизайн-токены в `src/assets/styles/tokens.css`, светлая и
тёмная темы через `data-theme`. Повторяющиеся блоки (`.text-control`, `.icon-action`,
`.alert`, `.form`, `.block`) — глобальные, дальше scoped-стили в компонентах.


**Фильтры — в композабле.** `useQueryFilters` держит единственный источник правды
в URL: и первая загрузка, и «назад» в браузере идут одним путём. Три страницы
используют его вместо трёх копий одного и того же разбора query и дебаунса.

## SMS-уведомления о новинках

Гость подписывается на автора по номеру телефона и получает SMS, когда в каталоге
появляется новая книга этого автора. Шлюз — [SMSPILOT](https://smspilot.ru),
API-1 (HTTP GET), на ключе-эмуляторе из документации.

Рассылку выполняет бэкенд при создании книги: он находит подписчиков всех авторов
новинки и отправляет по одному SMS на номер. Ключ шлюза во фронтенд не передаётся.
Здесь эту роль играет мок, поэтому клиент шлюза лежит в `src/mocks` — с настоящим
бэкендом весь этот код из сборки исчезает вместе с MSW:

```dotenv
# .env.production.local — отключает мок, и папка mocks вырезается из бандла
VITE_USE_MOCK=false
```

То же самое делает переменная окружения `VITE_USE_MOCK=false` на хостинге.

### Как устроено в моке

- [`src/mocks/sms.ts`](src/mocks/sms.ts) — клиент SMSPILOT: собирает GET-запрос,
  разбирает оба формата ответа (успех с `server_id` и ошибку с `description_ru`),
  никогда не бросает исключение — сбой шлюза не должен ломать создание книги.
- [`src/mocks/handlers.ts`](src/mocks/handlers.ts) → `notifySubscribers()` — после
  `POST /books` находит подписчиков всех авторов новинки и шлёт по одному SMS
  на номер (даже если он подписан сразу на двух соавторов). Результат каждой
  отправки пишется в журнал со статусом `sent` / `failed`.
- `PUT` и `PATCH` SMS не шлют: новинка бывает только одна.
- Журнал доступен по `GET /notifications?phone=` и показывается в разделе
  «Подписки» — видно текст сообщения, время и ответ шлюза.

### Что происходит, если книгу удалили

Отправленное SMS — исторический факт: запись остаётся, даже когда книги или
автора больше нет в каталоге. Но ссылка на удалённую книгу вела бы на 404,
поэтому бэкенд при удалении обнуляет `book_id` (и `author_id` при удалении
автора), а названия хранятся в самой записи отдельными полями.

Клиент решает по `book_id !== null`, рисовать ссылку или зачёркнутый текст
с пометкой «удалена из каталога». Тип `book_id: number | null` делает эту
проверку обязательной — забыть её и получить битую ссылку нельзя.

Альтернатива — флаг `book_deleted` с сохранением `book_id` — оставила бы больше
данных для аудита, но позволила бы отрисовать ссылку в никуда, просто
не посмотрев на флаг.

## Деплой

Настоящего бэкенда нет, поэтому на хостинг уезжает статика, которая сама себе
сервер: мок включён в прод-сборке (`.env.production`), конфигурация — в
[`vercel.json`](vercel.json) (SPA-fallback, прокси на SMS-шлюз, `no-store`
для воркера MSW).

> **Грабли при импорте в Vercel.** На экране импорта Vercel сканирует `.env*`
> в репозитории и предлагает завести найденные переменные — с **пустыми**
> значениями. Их нужно удалить кнопкой «−»: переменная окружения у Vite
> приоритетнее файла, поэтому пустая `VITE_USE_MOCK=""` отключит мок, и
> задеплоенное приложение не сможет загрузить данные.

## Тесты

237 тестов, Vitest:

- **Контрактные тесты мока** (`src/mocks/handlers.spec.ts`) — 45 штук. Гоняют все ручки
  через `msw/node`: конверт `{ success, data }`, пагинация, фильтры, поиск,
  коды 401 / 404 / 422 / 400, дубликат ISBN, запрет удаления единственного автора книги,
  корректность рейтинга ТОП-10 и учёт соавторов. Отдельный блок — SMS: одно сообщение
  на номер при двух соавторах, рассылка каждому подписчику, молчание при обновлении
  книги, запись сбоя шлюза в журнал без срыва создания книги. Шлюз в тестах
  подменён заглушкой — наружу запросы не уходят.
- **Покрытие спецификации** (`src/mocks/spec-coverage.spec.ts`) — парсит `api/*.yaml`
  и сверяет список операций с обработчиками мока в обе стороны. Новая ручка в спеке
  или лишняя в моке уронит сборку до код-ревью.
- **Интеграционные тесты страниц** — реальные компоненты, сторы, роутер и API-клиент
  против тех же хендлеров, общая обвязка в `src/test/support.ts`. `BooksListView`:
  рендер, фильтры из URL, пустое состояние, разное меню для гостя и пользователя.
  `AuthorsListView`: полный цикл удаления с подтверждением и отказ сервера.
  `LoginView`: клиентская валидация, ошибка сервера, успешный вход.
  `BookEditorView`: подстановка автора из `?author_id=`.
- **Сторы** — `auth` (вход, восстановление сессии, протухший токен), `books`
  (маппинг фильтров в параметры спеки, выбор PATCH/PUT, обработка ошибок),
  `subscriptions` (нормализация номера, журнал SMS, поллинг на фейковых таймерах:
  период, остановка, счётчик потребителей, тост только о новых записях).
- **Маска телефона** (`src/components/ui/PhoneInput.spec.ts`) — 19 тестов: маска
  по мере ввода, отбрасывание кода страны, фильтрация букв, лимит в 10 цифр,
  вставка номера в четырёх форматах, Backspace через разделители и отдельно —
  позиция каретки: после первой цифры, при перескоке через разделитель,
  при правке в середине номера и после вставки.
- **Утилиты** — валидация (контрольные суммы ISBN, нормализация телефона),
  форматирование, склонения, сборка query-строки, разбор `ApiError`.

```bash
npm test
```

Контрактный спек мока идёт в окружении `node`, а не `jsdom`: `File` из jsdom нельзя
передать в `fetch` Node — запрос с multipart-обложкой зависает. В браузере такой
проблемы нет, там `File` и `fetch` из одной реализации.
